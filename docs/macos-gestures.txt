Нативные жесты Android → Mac (экспериментально)

Обновите RustDesk на обоих устройствах. На Mac оставьте разрешённым
«Универсальный доступ» для RustDesk. Драйверы, отключение SIP и аккаунт
разработчика для этой функции не нужны. Подключение работает через обычный
интернет-сеанс RustDesk; Bluetooth не используется.

На Android в открытом сеансе нажмите кнопку режима мыши/касания на нижней
панели. Включите «Нативные жесты на Mac (экспериментально)». Настройка видна
только если Mac сообщил о поддержке. Она сохраняется на Android и применяется
со следующего жеста; выключенная настройка оставляет прежний путь ввода.

Сначала касанием активируйте нужное приложение на Mac. Затем:
  • сведите или разведите два пальца — изменится масштаб в приложении Mac;
  • двигайте два пальца вместе — прокрутится содержимое приложения Mac.
Точка между пальцами задаёт цель на удалённом экране с учётом масштаба
просмотра и Retina. Тип жеста фиксируется после порога распознавания: небольшой
дрейф пальцев не превращает уже начатую прокрутку в pinch. Чтобы сменить жест,
отпустите пальцы и начните новый. В новом режиме два пальца не масштабируют
локальное изображение Android. Одиночные касания и перетаскивание остаются
прежними; режим удержания кнопки виртуальной мыши также работает по-старому.

Ограничения
Это передача готовых жестов трекпада, а не отдельных контактов NSTouch и не
виртуальный HID Touch Screen. Системные жесты Mission Control, вращение,
инерция прокрутки и рисование несколькими пальцами не реализованы. Приложение
Mac должно поддерживать соответствующий жест и иметь активное окно.
Кодирование pinch использует недокументированные поля CGEvent. Оно проверено
на macOS 27.0.1; совместимость с другими версиями требует проверки. SkyLight
и привилегированные HID-entitlements не используются. Если жесты ведут себя
неправильно, выключите настройку, чтобы вернуться к прежнему управлению.

Проверки
  clang++ -std=c++17 -fobjc-arc -framework AppKit -framework ApplicationServices \
    res/macos-touch/native_gestures_test.mm -o /tmp/native-gestures-test
  /tmp/native-gestures-test
  cd flutter && flutter test test/macos_gesture_test.dart
  cargo test --locked --release --lib native_gesture_retina --features flutter
  cargo test --locked --release -p base protos::tests

GestureProbe.m использует тот же PostNativeGesture, что и RustDesk.
Сборка интерактивной проверки: sh res/macos-touch/build-gesture-probe.sh
Проверка в активном окне на MacBook Pro M2 Pro с macOS 27.0.1 подтвердила
доставку pinch через системную очередь и изменение масштаба содержимого.
Проверка нативного кодирования не отправляет ввод и не требует Accessibility.
Она проверяет pinch, прокрутку, фазы, числовую валидацию. Dart-тесты проверяют
порог распознавания, относительный масштаб, прокрутку и отмену. Protobuf-тест
проверяет неизменность старого wire-format. Тест Retina проверяет отдельный
монитор с отрицательным началом координат и масштабом 2.

Поверхность изменений
remote_input.dart: новая ветка только для включённого и поддержанного режима;
старые обработчики остаются после неё. remote_page.dart/model.dart/consts.dart:
настройка и загрузка её значения. message.proto/flutter.rs: отдельный вариант
PointerDeviceEvent и отправка через существующий sessionSendPointer без новой
FFI-функции. server/connection.rs: объявление поддержки, Retina-преобразование
только нового сообщения и отмена жеста при завершении потока ввода.
input_service.rs: новый macOS-обработчик после существующих проверок активности
ввода. build.rs/macos.rs: подключение модуля. Остальные платформы игнорируют
новый вариант. Старые сообщения touch не изменены.
