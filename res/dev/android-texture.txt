Android: аппаратное декодирование в текстуру

Путь кадра: сжатый H.264/H.265 в Rust -> JNI -> MediaCodec -> Surface ->
SurfaceTexture Flutter. Преобразование декодированного кадра в RGBA на CPU
в этом пути не используется. Сжатые данные копируются в буфер MediaCodec.
Следующий кадр передаётся в Surface после подтверждения получения предыдущего
через SurfaceTextureEntry.OnFrameConsumedListener. Ожидают максимум два уже
декодированных кадра; при перегрузке старый готовый кадр возвращается кодеку
без показа. Сжатые опорные кадры этим ограничением не отбрасываются.

В обычной сборке путь доступен через существующую настройку Android
«Аппаратные кодеки» → «Включить аппаратные кодеки». Предпочтение считывается
при создании подключения; после его изменения нужно переподключиться.
Специальный сборочный флаг не требуется. ANDROID_TEXTURE_DECODER=false
полностью выключает новый путь для контрольных сборок и отката.
Требуется Android 10/API 29 или новее.
Выбирается только аппаратный декодер; low-latency включается при его поддержке.
При ошибке или длительном ожидании входного буфера запрашивается ключевой кадр и до конца
сеанса используется старый программный путь. Запись сеанса также переводит
текущий видеопоток в программный режим.

Локальные инструменты находятся в ../.toolchains относительно репозитория:
Flutter 3.24.5, Rust 1.75.0, cargo-ndk 3.1.2, JDK 17, NDK r28c,
Android SDK 36, vcpkg 9e593bb18ea69cc5095e012465dcd675a822ed0d.
res/dev/android-env.sh задаёт окружение для одной команды.
RUSTDESK_TOOLCHAINS позволяет выбрать другое расположение инструментов.
Для локальной разработки использован bridge из CI базового коммита.
Новых flutter_rust_bridge API в изменении нет: Android взаимодействует через
JNI и MethodChannel. CI создаёт bridge обычным процессом проекта; локальный
codegen не требуется. Сгенерированные файлы по-прежнему не отслеживаются Git.
Для кросс-компиляции libsodium явно заданы llvm-ar/llvm-ranlib из NDK.
Финальная линковка использует --no-undefined: неразрешённые функции должны
останавливать сборку, а не обнаруживаться загрузчиком уже на телефоне.

Сборка из корня репозитория:
  bash res/dev/android-env.sh bash res/dev/build-android-texture.sh

Программная контрольная сборка из того же исходного кода:
  bash res/dev/android-env.sh bash res/dev/build-android-texture.sh false

Результат: target/android-texture/rustdesk-texture-{default|true|false}-arm64.apk.
Режим default собирается без Dart override; true — явное включение сборочного
допуска (настройка «Аппаратные кодеки» всё равно учитывается), false — контроль.
Обычный production pipeline build.py/CI не требует дополнительных аргументов.
У локальных тестовых APK проверяются подпись, applicationId, arm64 ABI,
отсутствие debug-флага, Dart-флаг аппаратного пути, одинаковая Rust-библиотека
в паре APK и 16-КБ выравнивание ZIP/всех ELF-библиотек. SHA256SUMS лежит рядом.
Обе тестовые сборки используют com.carriez.flutter_hbb.texturedev,
название RustDesk Texture Dev и локальную debug-подпись в release-режиме.
Они устанавливаются рядом с официальным RustDesk. Контрольную и аппаратную
сборки нужно сравнивать по очереди, заменяя одну другой через adb install -r.
Общие параметры приложения при такой замене сохраняются.

Перед первой сборкой Flutter нужны зависимости (flutter pub get), файлы bridge
из CI и библиотеки vcpkg для Android. Helper использует --no-pub, чтобы не
менять lock во время сравнения APK. SDK/NDK/JDK, кеши и бинарные библиотеки
не коммитятся. ../.toolchains находится вне корня Git; .toolchains внутри
репозитория также исключён .gitignore. Артефакты находятся в игнорируемом target/.

и предупреждений; информационные замечания в существующем коде остались.
На SM-F971B с Android 17/API 37 проверена загрузка исправленной нативной
библиотеки и запуск MainActivity. Первый запуск выявил пустой libsodium.a
из-за архиватора macOS; исправлены инструменты сборки и пересобраны оба APK.
Отдельная release-сборка default без Dart override проверена на этом телефоне:
настройка Hardware Codec ON -> изображение и HW / Surface, OFF после
переподключения -> изображение и SW / CPU. Настройка возвращена ON.

Проверка на устройстве:
1. Подключить телефон с USB debugging. Установить тестовый APK через adb install -r.
2. Внести параметры своего сервера в отдельное приложение, подключиться к Mac.
3. Проверить в adb logcat -s AndroidTextureDecoder имя аппаратного декодера,
   размер и отсутствие сообщения Switching to software decoding.
4. Сравнить true/false на одном разрешении, качестве, кодеке и типе соединения:
   прокрутка текста, перемещение окон, анимация; затем 10–15 минут нагрузки.
   Записать FPS, задержку ввода, нагрев и расход батареи. Debug APK для этих
   замеров не использовать. Температуру и заряд можно читать через
   adb shell dumpsys battery, тепловое состояние — dumpsys thermalservice.
5. Проверить масштаб/панораму, поворот и раскрытие Fold, переподключение,
   смену разрешения/монитора, переключение кодека и начало записи.

Монитор качества на Android:
- Decode path: HW / Surface — аппаратный декодер выводит в текстуру;
  SW / CPU — используется прежнее программное декодирование.
- Decoder: имя реально выбранного MediaCodec, например c2.qti.hevc.decoder.
- Input / decode FPS: принятые аппаратным модулем и декодированные кадры/с.
- Texture FPS: новые кадры, полученные Flutter через updateTexImage;
  повторное чтение той же временной метки не увеличивает счётчик.
  Это не измерение момента физического обновления дисплея телефона.
- Rust queue: число VideoFrame, ожидающих в существующей очереди Rust.
- Codec queue: ожидающие подачи сжатые кадры / лимит 4 и возраст самого
  старого ожидающего кадра. Внутренние буферы самого MediaCodec сюда не входят.
- Surface queue: уже декодированные кадры, ожидающие отправки в Surface / лимит 2,
  и число отброшенных готовых кадров с начала сеанса. Дополнительно максимум
  один кадр отправлен в Surface и ждёт подтверждения от текстуры.
- Fallback: причина ошибки аппаратного пути; остаётся видна в SW-режиме.
Статистика запрашивается только у открытого монитора на существующем
quality-status tick. Дополнительного таймера и покадрового логирования нет.
Диагностический лог выключен по умолчанию. Для подключённого телефона:
  adb shell setprop log.tag.RustDeskTextureStats DEBUG
  adb logcat -s RustDeskTextureStats:D
Выключить:
  adb shell setprop log.tag.RustDeskTextureStats INFO
Лог появляется только при открытом мониторе, не чаще одного раза в секунду.
Каждая строка содержит те же счётчики/очереди и sampleTimeNs; FPS вычисляется
по разности submitted/decoded/consumed между соседними строками и времени.
Это logcat; отдельный файл и фоновый таймер не создаются.
При кратковременном заполнении очереди JNI вызывающий поток теперь ожидает
свободный слот, не блокируя обработчик MediaCodec и не отбрасывая опорные кадры.
Если слот не освободился за 250 мс (1500 мс для ключевого кадра), сохраняется
переход на программный декодер с запросом ключевого кадра.

Поддержка и ограничения:
- Аппаратный путь предназначен для одного выбранного удалённого дисплея.
- VP8/VP9/AV1, старые Android и неподдерживаемые конфигурации остаются на
  существующем пути. Не заявляется поддержка HDR/4:4:4 аппаратным декодером.
- Стандартный счётчик FPS получает подтверждения получения текстурой при следующем
  входном пакете; последняя картинка перед паузой может попасть в соседний интервал.
  Готовность UI определяется первым выходным кадром в Surface, а счётчик —
  SurfaceTextureEntry.OnFrameConsumedListener закреплённого Flutter 3.24.5.
- Поведение MediaCodec, задержка и энергопотребление требуют проверки на телефоне.
- На SM-F971B/API 37 проверены HEVC 3024x1964, переподключения и FPS. Тесты
  поворота/Fold, длительной автономности и других моделей/кодеков не завершены;
  эти результаты не объявляются подтверждёнными для всех Android-устройств.

Wi-Fi macOS и AWDL: результат измерений на этом Mac
- По прямому LAN с включённым AWDL: около 51 FPS на выводе, примерно две
  паузы 90–110 мс в секунду; после паузы кадры поступают пачкой.
- USB / loopback исключил регулярные паузы. Выключение AWDL убрало их и по
  Wi-Fi; после обратного включения они вернулись (A/B/A-контроль).
- Изменение Android: раньше по USB декодировалось 62.41 FPS, текстура
  получала 58.28; с SurfaceFrameQueue — 63.00 / 63.00 FPS, без потерь.
  Это измерения накопительных счётчиков, не изменение формулы счётчика FPS.
- В 20-секундном LAN-прогоне без AWDL новая версия получила в текстуру
  62.32 из 62.87 FPS; оставались две отдельные сетевые паузы до 150 мс.
  Средние 60+ FPS не означают идеально постоянный интервал каждого кадра.
- По обычному ID через тот же relay/VPN без AWDL: 62.04 из 62.78 FPS,
  две отдельные паузы >80 мс за 20 с. Пользователь подтвердил исчезновение
  прежних регулярных полусекундных фризов. Затем AWDL возвращён UP,
  диагностическое логирование выключено, временный USB reverse удалён,
  включавшийся для USB/LAN-тестов прямой IP-доступ снова выключен.
Клиент не исправляет системные паузы радио. Опциональный временный режим:
  bash res/dev/macos-wifi-low-latency.sh 900
Он требует sudo, выключает AWDL на указанные секунды и восстанавливает его
по завершении, Ctrl+C, TERM/HUP. AirDrop/Continuity временно недоступны.
Если AWDL уже выключен, скрипт завершается без изменения его состояния.
Постоянная настройка/фоновая служба не устанавливаются. Этот режим не нужен
при USB-тесте; альтернативой Wi-Fi на Mac является проводное подключение.
Если системная служба сама включит AWDL в течение режима, скрипт его повторно
не выключает. Перед измерением следует проверять ifconfig awdl0.

Поверхность регрессии: проверка минимальности изменений
- AndroidTextureDecoder.kt и SurfaceFrameQueue.kt: новая Android-ветка теперь
  подтверждает получение Surface-кадра по PTS и ограничивает очередь готовых
  изображений двумя. Это устраняет замену ещё не полученного текстурой кадра.
  Индексы MediaCodec принадлежат одному worker; clear при reset/release
  удаляет ссылки на прежний кодек. При перегрузке возвращаются декодированные
  буферы, а аппаратное декодирование продолжается; таймер покадровой выдачи
  не добавлен. Остальные платформы и программный декодер не меняются.
- flutter/lib/models/android_texture.dart: новый монитор получает Surface queue
  и drops через уже существующий опрос статистики; собственного таймера нет.
- res/dev/macos-wifi-low-latency.sh: отдельная явная диагностическая команда;
  Android-приложение не меняет AWDL и не запускает этот скрипт.
- src/client.rs: Android/flutter-хуки создания декодера, обработки кадра и сброса;
  без зарегистрированной текстуры выполняется прежний путь. Для монитора
  передаётся Weak на существующую очередь, не удерживающий её между опросами.
- src/client/io_loop.rs: Android/flutter-хук геометрии при SwitchDisplay;
  нужен для правильного размера аппаратного потока после смены разрешения.
- flutter/lib/models/model.dart: запуск/закрытие Android-текстуры, событие первого
  изображения, допуск жестов без ui.Image, расчёт масштаба по размеру текстуры
  и сохранение положения/масштаба при закрытии сеанса с текстурой.
  При выключенном Hardware Codec или сборочном допуске сохраняются прежние ветки.
- flutter/lib/mobile/pages/remote_page.dart: показ Texture вместо CustomPaint
  только после готовности аппаратного изображения, с теми же scale/offset.
- MainActivity.kt: создание модуля и освобождение его ресурсов вместе с engine.
- ffi.kt: четыре новых JNI-метода; существующие методы не изменены.
- flutter/lib/common/widgets/overlay.dart: дополнительные строки и ширина
  монитора 280 вместо 200 только на Android. Для SW остаётся строка SW / CPU;
  платформы, отличные от Android, сохраняют прежний монитор.
- flutter/android/app/build.gradle: JUnit и opt-in dev-пакет/подпись/название;
  обычная сборка сохраняет прежние applicationId и подпись.
- flutter/android/app/src/main/AndroidManifest.xml: имя приложения из placeholder;
  в обычной сборке оно по-прежнему RustDesk.
- .github/workflows/flutter-build.yml: пять существующих JUnit-тестов модуля
  запускаются в aarch64 Android CI после сборки; остальные платформы без изменений.

Подмодуль hbb_common восстановлен на закреплённой версии без её изменения.
Код macOS-хоста, протокол и сервер не изменены.
